## What did not work

### 1. Worker MC env wrapper (r1) — did not bite

All four roles **repeated** their #1 problem from run #1: `MC_API_URL` /
`MC_USERNAME` absent at spawn; manual export every `mc` call. Quotes:

- navigator: "MC_API_URL/MC_USERNAME boilerplate STILL not injected into shell env"
- builder: "Bot server unreachable — card completed on parent handoff alone"
- crafter: "`environment_has_no_mc_vars: true` (repeat from w1-1780871693)"

Root cause confirmed by inspecting the live crafter process (pid 9993):

```
HERMES_HOME=/Users/foz/.hermes/profiles/crafter   # ← profile dir, not ~/.hermes
PATH=/Users/foz/bin:/opt/homebrew/bin:…:/Users/foz/.local/bin:…
                                            ^ no profile bin dir
MC_API_URL=<unset>
```

Two bugs compound:

1. **SOUL §Turn-1 has the wrong path expression.** It says
   `export PATH="$HERMES_HOME/profiles/<role>/bin:$PATH"`. But the worker's
   `HERMES_HOME` is *already* `/Users/foz/.hermes/profiles/<role>`. The
   expression resolves to `…/profiles/<role>/profiles/<role>/bin`, which
   does not exist. The wrapper actually lives at `$HERMES_HOME/bin`.
2. **Agents don't auto-execute SOUL Turn-1.** Even if the path were right,
   no role read SOUL and ran the export. They went straight to `mc status`
   cold and discovered the env piecemeal. The wrapper-on-PATH approach
   requires either the spawn process exporting the prepend automatically,
   or PATH manipulation inside Hermes's terminal-tool wrapper.

### 2. `mc inspect --mark` (r2) — flag rejected by worker's mc

Crafter ran `mc inspect --mark wheat_plot` and got **exit 1** (and similarly
for `wheat_chest`). Fell back to coord-based `mc inspect <x> <y> <z>`. The
new flag landed in repo `bot/cli/`, but the worker's PATH resolved `mc` to
`/Users/foz/.local/bin/mc`, which is a separate install that doesn't carry
the new code. Same root cause as §1 (wrapper not on PATH) — the wrapper
would `exec` the repo's `bin/mc` which has the new flag.

### 3. Observer-prep dimension bug

The script tp'd Tester into **overworld**, not **landfolk-test**. Fixed
in-line during the eval phase (one-word change in
`scripts/prep-wheat-verify-observer.sh`); first re-evaluate ran with the
wrong dim and returned 0/3 predicates; after fix → 2/3.

Per the plan, this would have been an `r8` regression catch.

## Recommendations for next remediation

1. **r1 fix-up (highest priority).** Either:
   - Correct SOUL §Turn-1 to `$HERMES_HOME/bin` (one-word path fix).
   - Better: have the spawn path (`hermes work kanban task`) inject the
     `bin` prepend automatically before invoking the terminal tool, so
     the agent doesn't need to remember.
   - Best: fix the underlying `env_passthrough` propagation so dispatcher
     exports reach the worker shell, then the wrapper becomes optional.
2. **r2 follow-up.** Confirm `~/.local/bin/mc` carries the `--mark` flag,
   or document that workers must hit repo `bin/mc` via the wrapper.
3. **Builder fragility.** Builder card "succeeded" by trusting the
   navigator's handoff without ever reaching the bot. If the navigator's
   survey had been wrong, the trial would have advanced on bad data. Add a
   minimal "verify with bot" gate in the agent-builder bundle.
4. **Acceptance predicate redesign.** `wheat` count > 60 fails when the
   crafter does its job. Replace with a chest-contains predicate (wheat
   deposited), or evaluate the predicate snapshot pre-harvest.
5. **`--mark` flag promotion (still cheap).** Add `mc farm_status --mark`
   (farmer #2 ask, twice). Symmetric with `mc inspect --mark`.
