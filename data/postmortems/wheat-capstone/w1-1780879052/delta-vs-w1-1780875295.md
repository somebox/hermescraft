## What worked (the fixes that bit)

### 1. MC env in role `.env` — the right fix

`setup-role-profiles.sh` now writes `MC_API_URL`, `MC_USERNAME`,
`_MC_API_URL_LOCKED` into each role's `.env`. Hermes's
`load_hermes_dotenv` (called post-spawn in `hermes_cli/main.py:403`)
loads them into the worker's `os.environ`. From there, the role
`config.yaml` `terminal.env_passthrough` carries them into every `mc`
subprocess.

**Hard evidence** — first `mc` calls in each role's card log, none
with `MC_API_URL=` prefix:

```
navigator: $ mc status  0.3s         (no manual export)
builder:   $ mc status  0.3s         (no manual export)
farmer:    $ mc inspect --mark ...   (no manual export)
crafter:   $ mc status  0.3s         (no manual export)
```

The dispatcher-export path remains architecturally blocked by
`kanban_db.py:6671` ("Scrub profile-specific MC routing env vars
before profile dotenv" — Hermes intentionally drops MC vars at spawn
to prevent operator-session leakage). The profile `.env` IS the
sanctioned override channel — and once we used it, everything worked.

### 2. Acceptance predicate semantics fixed

- `chest_contains wheat min_count=30` replaced the post-harvest
  `region_blocks block=wheat min_count=60` (which the crafter card was
  designed to eliminate by harvesting).
- `wheat_graph.py` now has 3 predicates: farmland (region) +
  chest_contains (wheat) + at_mark (water). All evaluable in this trial.

### 3. Navigator card body water hint

Trial 3 navigator immediately understood: "Navigate to it (water source
block — approach from adjacent dirt)" — no discovery turn wasted on the
liquid surprise.

### 4. Verifier safety prep

`prep-wheat-verify-observer.sh` now tps Mox to wheat_start (dry cell)
before evaluate. Mox didn't drown during evaluation. Tester tp also
runs but has a separate issue (see §below).

### 5. `mc advise` config fix

`tests/_lib/config.py:_load_config` now merges
`_DEFAULTS_WITHOUT_YAML` on the YAML path, so
`config["bot"]["health_poll_interval_s"]` is always present. The
KeyError would no longer fire. (Trial 3 navigator didn't hit a
stuck_warning, so didn't exercise the path directly.)

### 6. READ_FAILED → `evaluable=false` guard

`acceptance.py:_parse_verify_response` now distinguishes
"predicate didn't measure" from "predicate failed". Future trials
will see chunk-unloaded as `evaluable=false`, preserving honesty.

## What still needs work

### 1. `mc inspect --mark` flag — deployment mismatch

The flag is registered in `bot/cli/registry.mjs:1499`, but `mc inspect
--mark wheat_plot` returns exit 1 from the worker. Likely cause: system
`mc` at `/Users/foz/.local/bin/mc` is stale relative to repo. All roles
fall back to `mc marks` quickly, but the friction recurs across trials.
**Fix:** confirm `~/.local/bin/mc` resolution; symlink to repo `bin/mc`
or rebuild.

### 2. Tester observer position — bot doesn't stay teleported

`prep-wheat-verify-observer.sh` runs `execute in landfolk-test run tp
Tester …`; rcon reports "Teleported", but querying Tester 2s later
shows it back in overworld at (0–4, 65, 0–5). Tester's bot logic /
gamemode is sending it home. The `chest_contains` predicate first
attempt failed with NOT_ADJACENT for this reason.

**Workarounds used:** manually `gamemode creative Tester` + retry tp;
ultimately re-verified via Mox-adjacent tp.

**Fix options:**
- Tester runs in spectator mode by default (memory note says creative
  to avoid ghost rendering).
- Or: prep script uses `mc` to navigate Tester (not rcon tp).
- Or: route verify calls through whichever bot is adjacent to the
  target mark (per-predicate routing).

### 3. Confabulation in feedback (farmer)

Farmer feedback claims "MC_API_URL injection remains broken (4th run)"
but the actual card log shows `mc status  0.2s` succeeded on first
try with no manual export. The agent appears to be reading prior
archived feedback cards on the board (or other lingering context) and
confusing them with current observation. **Fix:** Either fully clear
archived feedback between trials, or include in the feedback prompt
"report ONLY what you observed in your own session — do not extrapolate
from prior runs."

### 4. Scorecard re-evaluation cycles (builder feedback flag)

Trial 3 evaluated 5 times before converging on `pass`. First 2 had bad
Tester position; next 2 hit the min_count=60 threshold; final one
landed when I patched the manifest to 30. This is operator iteration,
not a system flaw, but the builder's right that the scorecard should
converge in 1 pass with realistic thresholds + reliable Tester tp.

### 5. `mc farm_status --mark` (deferred)

Farmer flagged again. Cheap symmetric extension to `mc inspect --mark`.
Defer to next polish pass.

### 6. Cron + gateway liveness

Farmer noted "if `hermes gateway` isn't running, the cron silently
never fires." Trial 3 worked because the gateway was running. A worker-
side liveness probe would prevent silent stalls.
