## What broke

### Bug 1 — Agent-side `mc disembark` can't escape a stuck boat

Path: agent calls `/action/disembark` with **no** `emergency: true` flag. The dismount chain:
1. native `b.dismount()` — silent fail (Paper 1.21+)
2. sneak key — silent fail
3. PaperMCP `ride <user> dismount` — server returns ok=false (boat is somehow in a state where it can't drop the rider)
4. **Emergency RCON force-kill — SKIPPED because `opts.emergency === false`**
5. Return `DISMOUNT_REJECTED`

Reactive `auto_disembark_low_hp` passes `emergency: true` and gets the force-kill. The agent's CLI path does not. So a stuck-boat scenario at hp=20 leaves Steve stranded.

**Fix candidate:** when the agent calls disembark and all paths up to PaperMCP ride return failure AND `b.vehicle` is still set, escalate to force-kill even without `emergency: true`. The current `emergency` flag was added in Phase 1.3 for reactive-only callers; broaden it to agent calls when no other path freed Steve.

### Bug 2 — Reactive `engage_distant` fires at critical hp

At hp=3 with a drowned at 10b distance, reactive returned `advance_step (engage_distant)`. `flee_step` should always win below the critical-hp threshold (~4 hp). Likely a precedence bug in the reactive decision tree where the engage-distant arm is checked before the critical-hp arm.

**Fix candidate:** in `bot/lib/runtime/reactive.js`, move the critical-hp check above the engagement arms. Verify with a unit test on the decision tree.

### Bug 3 — Steve loses his iron_sword

Started with iron_sword, ended fighting with wooden_axe at hp=3. The reactive layer or `mc eat` flow swapped the held item. Need to instrument the equip flow to surface why iron_sword got swapped out.

### Bug 4 — Agent strategy collapse near base

After being freed from the stuck boat, Steve never re-located W1 (-300, 63, -100). He wandered NE to (495, -722) — opposite direction. The agent's recovery logic from the "stuck on shore" envelope didn't carry the W1 target forward.

This is partly a prompt/persona issue, partly a "no surfaced advise call" issue. The agent should have run `mc advise --reason="lost route to W1"` instead of wandering.
