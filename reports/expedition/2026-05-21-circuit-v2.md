## Root cause: brain doesn't reach for rescue verbs

The persona prompt mentions `mc escape` and `mc place_boat`. The
circuit-v1 prompt added the boat workflow. Both circuit-v1 and
circuit-v2 the agent ignored both verbs when in real trouble.

**Why?** A few hypotheses:
1. **LLM cadence vs. drowning timer.** Agent decision loop is ~5-15s
   per turn. Drowning kills in ~30s of submersion. By the time the
   agent observes "I'm in water" and plans a response, half the
   window is gone. It picks a quick action (`mc stop`, `mc jump`)
   over a longer process (`mc escape` involves equipment + multi-step).
2. **Persona prompt hedging.** The prompt says "don't `mc escape`
   from dry land — that's for in-water rescue". This is meant as a
   safeguard but reads as "escape is a niche thing", de-prioritizing
   it.
3. **No reactive auto-trigger.** Combat already has a reactive layer
   (`bot/lib/runtime/reactive.js`) that auto-flees creepers within
   6m, escapes lava, etc. **There's no equivalent reflex for
   drowning.** Water is handled only via brain decision.

## The fix: reactive water-watchdog (filed as task #17)

The existing reactive layer (`bot/lib/runtime/reactive.js:65`) ticks
every 400ms with hazard checks. It handles creepers, lava, fire.
**Adding "if foot_in_water for >2 ticks → auto-call escape" closes
the gap.** Same pattern. The bot rescues itself; the brain learns
about it from a log line and moves on.

This is what "trustworthy body" actually means in practice: for
sub-second emergencies, the body acts before the brain catches up.
