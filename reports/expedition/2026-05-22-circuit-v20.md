obstacles. Ran out → STUCK_IN_WATER repeatedly because escape's
boat_fallback needs a boat in inventory.

The agent did **not** call `mc craft oak_boat` proactively when its
supply dipped. It also can't easily — needs logs in inventory first,
which means chopping wood, which means navigating back to a tree.

### Agent strategy opacity

Agent declared at start: *"W1 is closest — heading to the mining
outcrop now"*. Then went silent — all subsequent calls wrapped in
`hermes_tools.terminal` Python imports, hiding both commands AND
reasoning from the log viewer. User had no way to see what Steve
was actually doing.

Shipped this session — these two fixes don't show up in scorecard
counts but improve postmortem fidelity for future runs:

- exp_watch.py now prefixes think/asst/tool lines with HH:MM:SS so
  reasoning aligns with positions/events.
- exp_lib.py poll-once now emits `goal_change` + `mount_change`
  events when bot state transitions.

Worth investigating separately.
