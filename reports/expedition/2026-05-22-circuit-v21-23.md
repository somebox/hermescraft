## What worked — the ferry primitive

The new `mc sail_to` action is **structurally complete and live-validated.**

In v23, the agent called `mc sail_to -300 63 -100` twice. Both times
the primitive responded with:

```
ok: false
error:
  code: NO_NAVIGABLE_ROUTE
  message: "Can't plan a water route: Water near start is a tiny pond
    (2 cells reachable). Walk to a real shore first with mc bg_goto.
    Suggestion: walk to a real shore first (mc bg_goto to a coast cell)."
  observed_state:
    water_route_error: POND_DISCONNECTED
    water_route_state: {entry_water, cells_in_pond: 2, ...}
  next_action_hint: "mc bg_goto <coast coords>  # then mc sail_to again"
```

This is **exactly the v15-v20 trap closed**: pre-fix, the agent
would have placed a boat in that 2-cell pond, mounted, sailed 1
block, gotten stuck, lost the boat, ended stranded. With `mc sail_to`,
the body refused upfront with a clear reason and a path forward.

## What still needs work — agent compliance

The agent honored "use mc sail_to" in v23's reasoning ("Using the
ferry service to cross") but:

1. **Habit override on cold start.** v21 + v22 first journey was
   `mc board` → `mc sail` chain despite the skill update. Only after
   the hardened "🚨 RULE: MUST call mc sail_to" prompt did the agent
   try sail_to first.

2. **next_action_hint ignored.** When `mc sail_to` returned
   `POND_DISCONNECTED` with hint `mc bg_goto <coast coords>; then mc
   sail_to again`, the agent didn't navigate to a different shore.
   Instead it fell back to `mc board` (which then placed a boat in
   the same pond — exactly what the refusal was warning against).

This is the v12/v20 pattern repeating: the agent processes errors
as "this verb failed, try a different one" instead of "this verb told
me what to do next, follow the hint." Body cues aren't enough — the
LLM needs explicit reinforcement that next_action_hint is the
authoritative instruction.
