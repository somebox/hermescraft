Hermescraft Architecture

A visual guide to the operating model: who does what, how cards flow, where memory lives, and how the team improves itself.

1 · Vocabulary

Six categories. Each has a color, shape, and role. The same shape language is used throughout so relationships are readable at a glance.

Role
An architectural concern: planning, allocation, execution, review. Abstract.
Bot
A Minecraft body. Mineflayer process + registry entry. pip, mox, zee.
Agent
A Hermes profile holding expertise (SOUL + skills + memory). Names start with @. @miner, @navigator.
Workspace
Shared storage for state and code. Git-backed. The team's collective memory.
Card
A kanban task. assignee=<agent> + optional metadata.bot=<bot> for bot-bound work.
Human
The operator. Sets goals, reviews, intervenes on edge cases. Not the orchestrator.

6 · Many cards have no bot

Many cards do not need a Minecraft body at all. Bot-less cards run in parallel with in-world execution and do not consume bot capacity.

Bot-bound   @miner driving pip

Needs a body in the world.
  • Spawn layer injects MC env → drives a body in the world
  • Holds per-bot lease — one card at a time per bot
  • Writes handoff metadata on complete (position, inventory delta)

Bot-less   @crafter · material budget

Pure data work — reads the shared workspace, writes a budget.
  • No MC env injected — no body needed
  • No per-bot lease — any number can run in parallel
  • Reads workspace + recall; writes comments or workspace files

10 · Recall stream: episodic memory the fleet shares

A host data API holds one append-only stream of sightings. The fleet writes to it and reads from it. Recall is episodic memory: what one worker sees can guide the next worker's card.

1 · See
@farmer on zee spots iron during a scene scan
→
2 · Report
recall.resource("iron_ore")
→
3 · Persist
Host API stores the event with dedupe window
4 · Plan
@planner reads a new [MINE] intent
→
5 · Recall
Top hits injected into the card body before dispatch
→
6 · Wake
@miner on pip wakes already knowing where to go

Live   Host data API

Append-only stream, high write rate, transactional reads. Also hosts fleet state, capacity forecasts, and dispatch logs.

Compacted   Git workspace generated/

Low write rate, diff-reviewable, snapshot-stable. Compaction cards bridge stream → git, archived by watermark.

What recall is not: not a chest database, not a region authority, and not a replacement for marks. Recall is episodic, marks are committed agreements, and workspaces are audited artifacts.

12 · The hard parts, plainly

Conceptual gotchas worth holding in mind.

ConstraintHermes scheduling is board-wide, not per-bot

v0.15 binds assignee at kanban_create (not at dispatch) and caps max_in_progress board-wide, not per-assignee. Our per-bot mutex lives in the bot lease + landfolk plugin, not in Hermes core. Don't expect upstream features to retire it.

PrimitiveBot lease: checkout, renew, release

Agents explicitly mc bot checkout a registry body, renew while acting, and release when done. The lease lives in ~/.hermes/bot-leases.db with conditional writes and lease_version fencing. Ranking: explicit --bot, capability filter, continuity (bot_last_mark), nearest (--near), LRU tie-break.

Tool fitDelegation is narrow

Synchronous, parent-bound, non-durable, max depth 3. Not a substitute for phase-as-card outer work. Useful only for intra-phase specialization inside short bot-less cards (e.g. @crafter material budgets).

DisciplineSkill bundles fence behavior

@crafter doesn't dig holes because mc dig isn't in its loaded catalog. Discipline is structural — the model can't reach for verbs it doesn't know about. Bundle quality is architecture quality.

SequenceBuild observability first

Before binding logic, ship the dashboard lease panel + fleet-state file + recall stream skeleton. Validate that what you see matches reality. Only then add dispatch scoring, maintenance, preemption. Each step reversible; no big-bang.

DisciplineRecall is episodic; marks are committed

Three storage cadences, three purposes. Recall stream = anyone-can-write sightings. Marks = committed coordinates the fleet agrees on. Workspace = audited, designed content. Don't reimplement locations-base.json inside recall; compaction may produce marks, never replace them.

Tool fitmc verify: deterministic acceptance predicates

Workers self-check completion and overseers validate acceptance with structured predicates: chest_contains, inventory_contains, at_mark, region_blocks. Response distinguishes "evaluated and false" from "could not evaluate" with explicit error codes and retry_safe flags. Replaces vague natural-language success_when clauses with testable checks.

Custom layerRecall inject: task-time context into card body

Before a worker sees a card, the dispatcher shifts relevant recall bullets into the body—nearest resources, recent damage, blockages. This is the recall inject step: task-time memory, not prompt engineering. The worker wakes already knowing where to go.
