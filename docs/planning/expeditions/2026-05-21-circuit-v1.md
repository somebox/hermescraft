## Root causes & bug data

### RC1 (severe) — Base location is a nav trap

The base at (350, 63, -595) is on a small peninsula. South and east
edges are open ocean. The expedition prompt didn't document safe exit
directions, so Steve's pathfinder picked a "shortest path" through
water.

**Fix candidates:**
- **Document exit paths in the prompt** — "from base, ALWAYS exit
  going west (door at X,Y,Z) or north (clear land)". Cheap.
- **Move the base** — relocate to a more landlocked area for QA tests.
  Disruptive.
- **Pre-bridge the south/east shores with cobblestone** during setup —
  guarantees a safe exit in every direction. Medium effort.
- **First-leg whisper from re44** — auto-send a directional hint when
  Steve announces a waypoint. Already used as fallback in exp5/exp6.

### RC2 (high) — `mc escape` ran 15s without recovery in deep ocean

Despite the `RC1 swim-up` fix (commit `d16754d`) that was supposed to
spam jump for ~3.75s and surface the bot before scanning land, escape
returned `[error]` after the full 15s timeout. Two interpretations:
- Steve was deeper than the 25 jump ticks can lift (>10 blocks down)
- Or the surface scan still couldn't find shore within 16 blocks once
  surfaced (large open ocean)

Both are real conditions the new code only partially handles. Next
step: instrument the escape function to report which phase failed
(swim_up timed out? cardinal scan found nothing? pillar-up failed?).

### RC3 (high) — `mc place_boat` failed 11 times in deep water

Even with the test-world bug fixed in commit `631dbb5`, place_boat
couldn't land a boat. Likely Steve was at a water-water-water column
with no adjacent solid stance block (place_boat requires a dry stance
adjacent to the target water cell). Task #7 (auto-adjust within 3
blocks) becomes more urgent — without it, the bot has no way to find
a workable target in open ocean.

### RC4 (medium) — Death detection has a false-positive

The `death` event fired at T+0:00 with `items_lost = ""` and
`deathNumber=2` (carryover from prior session). The `exp_lib.py`
poll-once logic only checks `seconds_ago < 35` and assumes that means
"new death". Should also check `deathNumber > last_seen_death_number`
to avoid stale-death flags.

### RC5 (medium) — Discovery rate is low even when stations aren't reached

Steve had wheat in inventory, knew W5 was about animals, but never
called `mc breed`, `mc milk_cow`, `mc feed_mob`, etc. The prompt
mentioned the goal but didn't enumerate verbs. The persona prompt
covers some primitives but not specialised ones like breeding.

This is the "discovery gap" the goal-only prompt was meant to expose
— success. Postmortem deliverable: which clusters need more skill/
persona coverage?
