# Expedition / Long-Run QA Logging Convention

Reliable, repeatable structure for in-game QA test runs. All test artifacts
live under `/tmp/hermescraft/runs/<RUN_ID>/`. The `current` symlink always
points at the active run so monitoring scripts can find logs without knowing
the RUN_ID.

## Run identifiers

`<RUN_ID>` = `YYYYMMDD-HHMMSS-<slug>` (e.g. `20260519-2300-expedition`).
Generated by `scripts/exp.sh start <slug>`. Lower-kebab-case slug.

## Files inside `/tmp/hermescraft/runs/<RUN_ID>/`

| File | Format | Purpose |
|---|---|---|
| `meta.json` | JSON | Fixed metadata: start_ts, slug, prompt_path, agent_pid, bot_pid, waypoints, loadout, expected_duration_min |
| `agent.log` | Text | Full hermes agent stdout (the boxed-up tool calls + assistant messages) |
| `bot.log` | Text | Bot's node-server stdout |
| `positions.jsonl` | JSONL | Append-only: one line every 30s with `{ts, x, y, z, hp, food, holding, task_action, task_status, deaths}` |
| `events.jsonl` | JSONL | Append-only structured events: `{ts, kind, ...}` — kinds: `death`, `respawn`, `low_hp`, `low_food`, `nav_error`, `chat_sent`, `chat_received`, `midcheck` |
| `midchecks/T+<N>m.log` | Text | Snapshot at given elapsed time — pos, inv, deaths, recent cmds |
| `summary.md` | MD | Generated by `exp.sh stop` — final state, distance covered, top errors, postmortem template |

## Symlinks

- `/tmp/hermescraft/runs/current` → `<RUN_ID>` directory of the active run.
  Cleared on `exp.sh stop`. Monitoring scripts use this — never hardcode the RUN_ID.

## Convention rules (enforced)

1. **Never write test artifacts outside `/tmp/hermescraft/runs/<RUN_ID>/`.**
   The agent's wrapper script DOES still write to `/tmp/hermescraft/steve-agent.log`
   for back-compat with `scripts/watch-steve.py`, but the canonical copy is at
   `runs/<RUN_ID>/agent.log` (the test harness symlinks them).
2. **Position polls go to `positions.jsonl`**, not to scattered midcheck files.
3. **Events go to `events.jsonl`** in append-only JSONL — never edit historic lines.
4. **All scripts must accept `<RUN_ID>` as an optional arg defaulting to `current`.**

## Scripts

| Script | Synopsis |
|---|---|
| `scripts/exp.sh start <slug>` | Set up run dir, restock Steve, launch agent + position poller |
| `scripts/exp.sh watch` | Live-tail thinking + tool calls + positions + events (merged into one stream) |
| `scripts/exp.sh midcheck [<label>]` | Snapshot current state into `midchecks/T+<elapsed>.log` |
| `scripts/exp.sh stop` | Kill agent, write `summary.md`, clear `current` symlink |
| `scripts/exp.sh status` | Print active run's current state (pos, time elapsed, item count) |
| `scripts/exp.sh analyze [<run-id>]` | Compute stats from positions.jsonl + events.jsonl |

`scripts/exp_lib.py` is the canonical parser for `mc status` / `mc task` /
`mc deaths` (handles edge cases like `holding` being a string vs object).
Used by all the subcommands above — change it once, every command picks
it up.

`scripts/exp_watch.py` is the merged live-tail (called by `exp.sh watch`).
Polls the newest hermes session JSON for new assistant content / reasoning /
tool calls, plus the current run's `positions.jsonl` and `events.jsonl`.
Colour-coded:

| Colour | Stream |
|---|---|
| gray | reasoning / thinking |
| cyan | assistant content |
| green | tool calls |
| red | tool errors, death, low_hp, nav_error |
| dim | position samples (Δ-distance per tick) |
| yellow | other events (midcheck, etc) |

## Recommended four-pane observation setup

For a run you'll be watching live:

```bash
# Pane 1 — merged: thinking + tool calls + positions + events
scripts/exp.sh watch

# Pane 2 — advise/scene digests (LLM perception output)
scripts/watch-advise.py

# Pane 3 — quick one-shot snapshots (run on demand)
scripts/exp.sh status        # how far has Steve moved?
scripts/exp.sh midcheck      # write a timestamped file to runs/<id>/midchecks/
scripts/exp.sh analyze       # paces, event breakdown

# Browser
http://localhost:4001/       # FPV viewer (what Steve sees)
http://localhost:3001/dashboard  # bot's built-in dashboard
http://localhost:3000/       # fleet dashboard (start with ./start-dashboard.sh)
```

`scripts/exp.sh watch` subsumes the old `scripts/watch-steve.py` for
expedition runs — same hermes session JSON parsing, but layered with
positions + events. Use `watch-steve.py` directly only outside a run
(when there's no `current` symlink).

## Why this structure

- **Per-run isolation:** No more mixing exp1/exp2/exp3 logs in /tmp root.
- **JSONL for time-series:** trivial to grep, parse, stream into pandas, plot.
- **Symlink for "current":** monitoring scripts don't have to be re-pointed
  between runs.
- **Append-only events:** post-mortem has full chronology even after the agent dies.
- **Deterministic paths:** any script can find logs by convention, not by ad-hoc
  filename guessing.
