# Feature Comparison: LLM-Driven Game Projects vs. Research Papers

| Dimension | Game Projects | Research Papers |
|---|---|---|
| **Action Representation** | **Generative Agents** uses natural language as the universal action interface — agents describe their actions in plain English, which a sandbox engine (Smallville) interprets into game-world state changes (e.g., "Isabella makes breakfast" → tree falls, fire starts, food appears). **Voyager** uses a programmatic action space — the agent generates executable JavaScript skill code via GPT-4, interacts with the Minecraft Java Edition API directly, and builds a reusable skill library over time. **GamingAgent** frames actions as structured game moves across diverse genres (board games, card games, RPGs, puzzles), providing a unified action API per game with JSON-format inputs/outputs for LLM/VLM evaluation. | **MineDreamer** represents actions as visual sub-goal images — before executing any motor command, the agent generates a chain of intermediate first-person-view snapshots that serve as concrete step-by-step action targets. **CausalMACE** models actions through causal graphs, where each action is a node with explicit upstream causes and downstream effects, enabling agents to reason counterfactually about whether an action will advance a cooperative goal. **Echo** treats actions as one of five experience dimensions (process) — actions are stored with their structural context, attribute preconditions, functional outcomes, and interaction partners, enabling fine-grained retrieval and transfer. |
| **Planning Approach** | **Generative Agents** uses a reflective planning hierarchy: agents maintain a daily plan (high-level intentions), decompose it into hourly actions, and periodically reflect on past observations to update beliefs and future plans. **Voyager** uses curriculum-driven iterative exploration — the LLM proposes goals based on its current skill inventory and world progress, attempts them autonomously, and the system self-improves by adding successful skills to a growing library. **GamingAgent** treats planning as a byproduct of model reasoning — the framework evaluates how well different LLMs/VLMs plan multi-turn strategies within each game's rule set, with performance metrics (win rates, reward accumulation) serving as the evaluation signal rather than an explicit planner. | **MineDreamer** introduces Chain-of-Imagination (CoI): the agent first generates a sequence of imagined intermediate visual states from the current observation, then executes actions to match each imagined state in order. This bridges the gap between high-level language instructions and low-level visual control. **CausalMACE** decomposes cooperative tasks via causal reasoning — agents identify causal dependencies between sub-tasks (e.g., "must collect wood before crafting planks") and plan jointly by sharing their causal models, enabling coordinated multi-agent execution on long-horizon tasks. **Echo** separates planning from execution by providing transferable experience snippets — a planner module retrieves relevant past experiences from the Echo memory and adapts them to the current task context, achieving faster convergence on new tasks than learning from scratch. |
| **Memory Model** | **Generative Agents** implements a stream-based episodic memory with three tiers: (1) short-term observation stream (recent events), (2) reflection (higher-level summaries synthesized from memories), and (3) retrieval — memories are scored by recency, importance, and relevance to the current context. Agents' personalities emerge from what they remember and how they reflect. **Voyager** uses a persistent skill code library as its memory — successful JavaScript programs are stored with descriptions in a vector database, and the agent retrieves relevant skills at plan time rather than remembering raw experiences. **GamingAgent** has no built-in memory architecture — it relies on the LLM's context window for in-game memory, with the framework focusing on evaluation rather than agent persistence across sessions. | **MineDreamer** uses the chain-of-imagination as a working memory mechanism — the sequence of imagined visual states serves as a short-term plan that guides moment-to-moment action, but there is no long-term persistent memory between episodes. **CausalMACE** implements shared memory via causal knowledge graphs — agents maintain a joint representation of causal relationships they've learned about the environment and task structure, which grows as they collaborate across episodes. **Echo** has the most sophisticated memory model of all six systems: a five-dimensional experience decomposition (structure, attribute, process, function, interaction) stored in a retrievable database with cross-task transfer. Experiences are embedded and retrieved using multimodal similarity search, with only the most transferable knowledge (the "echo") being applied to new tasks, achieving 1.3x-1.7x speed-ups. |

## Key Takeaways

- **Generative Agents** and **Voyager** are the most complete systems — they ship real, playable agents — but their memory models are simpler than what papers like Echo propose.
- **Echo**'s five-dimensional memory model is the most sophisticated across both columns, but it's a paper contribution without a public code release (yet).
- **MineDreamer**'s chain-of-imagination is a genuinely novel planning mechanism that no existing project (Voyager, Generative Agents) implements — projects could benefit from adopting visual sub-goal planning.
- **CausalMACE** is the only entry tackling multi-agent coordination explicitly; among projects, only **Generative Agents** simulates multi-agent worlds, but without causal reasoning.
- **GamingAgent** is the odd one out — it's more of a benchmark than an agent system, but it fills a gap the papers ignore (cross-genre evaluation beyond Minecraft).
